## ADR-029 ★★ Q2 异构机队必须整体投入；派发键必须含最小松弛量

**背景（问题）**

Q2 旧解为 **14 架次（全部 C 型）/ 完工 5.18 h / 准时率 55.0% / 53 条时限违规**，
并据此在论文中写下"首批保障时限在现有资源配置下**物理不可行**、任何调度算法都无法消除"。
复核后确认该结论**建立在三个建模缺陷之上**，不是题目的性质。

**根因（三个缺陷，按影响排序）**

| # | 缺陷 | 机理 | 证据 |
|:--:|---|---|---|
| 1 | **异构机队被退化成单一机型** | `fleet_mode="auto"` 只构造 A/B/C 三个**同构**机队，注释理由是"调度器按机型分池，方案机型必须统一"。该理由**不成立**：`schedule_ordered` 按 `pools[plan.type_code]` 取资源，各机型池彼此独立，混合机队天然可调度 | 题目原文即"**异构**无人机多点多架次运输调度"；8 架只用了 2 架 ⇒ 并行度剩 1/4 |
| 2 | **首批专架次机型没铺开** | 8 个服务区首批截止 3600 s，每区仅约 17 kg（任何机型都装得下）⇒ 瓶颈是"能同时起飞几架"。旧 seeding 取 `type_order` 首个（最大机型 C），而 C 只有 2 架 ⇒ 首轮仅 2 架起飞 | 实测首批 30 箱中 17 箱超时 |
| 3 | **派发键在"还没人违规"时退化为能耗优先** | 首轮开工时 `n_fb`/`fb_late`/`n_exp`/`exp_late` **全为 0**，排序落到 `ev.energy_kwh` ⇒ 首轮机位被"顺路的小架次"占满 | `t=0` 的 8 个机位有 2 个给了 S001 的第二个架次，S002/S012/S013 被推到 5800~7800 s（凭空 +5 箱超时） |

附带缺陷 4：`proxy_dispatch` 把机数/电池数当**标量**，隐含"所有机型共用一个池"。

**决策**

1. `solve()` 的候选机队加入**真实混合机队**（A×4+B×2+C×2），并给出三种装配策略
   （大机型优先 / 小机型优先 / 机队摊平），由**真实调度结果**统一评分取优。
2. `construct(..., fleet_counts, load_balance)`：首批专架次按键队槽位（4A→2B→2C）**轮转**挑机型；
   新开架次加 `w · 本机型已开架次数 / 该机型架数` 摊平惩罚（使架次分布 ≈ 4:2:2）。
3. `schedule_dispatch` 派发键改为
   `(n_fb, fb_late, n_exp, exp_late, **slack**, energy)`，其中
   `slack = min(时限 − 交付时刻)` —— **least-laxity-first**。
4. `proxy_dispatch(objective_breakdown)` 的 `resources` 支持
   `{机型: (机数, 电池数, 满充时间 s)}`，**按机型分别排队**。

**效果（Q1 不变，Q3/Q4 同步重算）**

| 指标 | 旧（缺陷版） | 新 |
|---|---|---|
| Q2 架次数 | 14（全 C 型） | **28**（A14+B8+C6，8 架全投入） |
| Q2 能耗 | 77.94 kWh | 82.30 kWh（+5.6%） |
| Q2 完工时间 | 5.18 h | **2.45 h**（−54%） |
| Q2 准时率 | 55.0% | **100.0%**（80/80 箱） |
| Q2 违规条数 | 53（全为时限类） | **0**（18 类检查全通过） |
| Q3 | 运输 14 + 中继 14 / 87.88 kWh / 5.19 h | 运输 28 + 中继 **24** / 86.62 kWh / **2.84 h**，24-24 覆盖 |
| Q4 原子单元 | 2（S014 独立 + 其余 14 区） | **5** ⇒ **K=2 与 K=3 均可直接合并得到（改动 0 架次）** |

**可行性论证（替代原"不可行性论证"，论文 5.4 节）**

- 60 min 档服务区数 = **8**，题目机队 = **8 架** ⇒ 只要每区各占一架机，8 个区可在 `t=0` 同时开工。
- 2 阶段充电不影响首轮：初始 SOC 均为 100%，14 组电池足够 8 架同时起飞。
- 实测最晚首批交付 **3587 s < 3600 s**（S006，余量仅 12 s）；120 min 档最晚 6464 s、180 min 档最晚 6851 s。
- 理论最少架次数 = ⌈758 kg / 320 kg每轮⌉ = 3 轮 × 8 架 = **24**（实际 28，装箱效率 86%）。

**红线 / 注意**

- ⚠️ **不要再把"首批时限物理不可行"写进论文**。若要论证可行性，用 8 架机口径重算。
- ⚠️ `slack` 项对鲁棒性关键：资源周转受扰动时仍优先保护最紧时限。
- ⚠️ Q4 的原子单元数由 Q3 方案形态决定，**不得硬编码**；改完 Q2/Q3 必须重跑 Q4 并复核论文数字。
- 诊断脚本：`scripts/diag/q2_tradeoff_sweep.py`、`q2_force_type.py`、`q2_firstbatch_bound.py`、
  `q2_firstbatch_dedicated.py`、`q2_objective_vs_schedule.py`。

## ADR-030 ★★ 目标函数必须用"真实调度器"判定违规；压架次数靠真实口径合并

**背景（问题）**

ADR-029 之后 Q2 为 **28 架次 / 82.30 kWh / 2.45 h / 准时 100% / 0 违规**，
但逐架次装载率只有 **71%**（质量）/ 69%（体积），而理论下界是 **24 架次**
（758 kg ÷ 每轮 320 kg = 2.37 → 3 轮 × 8 架）。还有 4 个架次的余量压不下去。

**根因：两套判定口径并存（proxy vs real）**

| 用途 | 用什么 | 问题 |
|---|---|---|
| `local_search` 的目标函数 | `proxy_dispatch`（**乐观下界**）| 估的开工时刻偏早 ⇒ **低估违规** |
| 上报结果的违规判定 | `schedule_dispatch`（真实排程）| 与目标函数不一致 |

后果：把架次权重从 0.05 提到 0.2 以上，架次数确实压到 **25**，
但真实排程**冒出 4 箱超期**（准时率 95.0%），而目标函数完全看不见。
细扫权重得到的前沿是 **26 架次@0 违规 ↔ 25 架次@4 违规**，
且 `violation_point` 取 1 或 1e3 **结果逐位相同**——直接证明目标对真违规是盲的。
（另：放宽 `max_group` 3→6 完全无效，说明自加的站数上限不是紧约束；
紧的是 A 型**体积**上限 0.06 m³，只装得下约 2 箱。）

**决策**

1. 新增 `consolidate_real()`：以「**真实调度器判定 0 违规**」为**硬前提**、
   以「**架次数最少**」为唯一方向，反复尝试
   ① 两两合并（容量/能量不可行时**升级机型**重试）；
   ② 单服务区整装（同区货箱用更大机型重装）。
   **每个候选方案都过一遍真实调度器**，不通过即回退。
   这等于把题目「应满足…时限要求」读成**约束**，在其后做字典序
   `(违规箱数, 架次数, 能耗, 完工时间)`。
2. 修一处真 bug：`local_search` 的 **relocate 走法漏了 `frozen` 判断**，
   会把箱子从硬期限专架次里搬走（move 2/3 都有判断，只有 move 1 没有）——
   这正是提高架次权重后立刻出现首批超时的直接原因。
3. `Q2Weights` 新增 `violation_point`（每违规箱权重），把时限的**约束**地位显式化；
   默认仍为 1.0，保持向后兼容。

**效果**

| 指标 | ADR-029 后 | ADR-030 后 |
|---|---|---|
| Q2 架次数 | 28（A14+B8+C6） | **25**（A8+B10+C7） |
| Q2 能耗 | 82.30 kWh | **77.30 kWh** |
| Q2 完工时间 | 2.45 h | 3.02 h |
| Q2 准时率 / 违规 | 100.0% / 0 | **100.0% / 0** |
| 质量装载率 | 71% | **79%** |
| Q3 | 28 运输 + 24 中继 / 86.62 kWh / 2.84 h | 25 运输 + **20 中继** / **82.14 kWh** / 3.15 h |
| Q4 | 5 个原子单元，资源 31/33/36 | **3 个原子单元**，资源 **32/34/37** |

**架次数与能耗同时下降**，代价是完工时间 +0.57 h；25 架次距理论下界 24 仅 1 个架次。

**红线 / 注意**

- ⚠️ **不要让目标函数与上报口径分叉**：任何以代理/近似估计为准的评分，
  都必须有一个**用真实调度器复核**的最终闸门，否则优化器会朝错误方向使劲。
- ⚠️ 提高架次权重是**陷阱**：单靠权重会牺牲时限而目标看不见。
  正确做法是"硬前提 + 真实复核"的合并，而不是调参。
- ⚠️ Q2 结果一变，Q3→Q4 与论文 / otheragent 全部要重跑（本 ADR 已同步）。
- 诊断脚本：`q2_packing_efficiency.py`（装载率/碎片化/轮次下界）、
  `q2_weight_regimes.py`、`q2_sortie_weight_fine.py`、`q2_maxgroup_grid.py`、
  `q2_consolidate_sweep.py`。
