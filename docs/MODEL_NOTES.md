## Q1 单点往返运输能力与货箱组批方案

### 1.1 问题结构

每个架次 `p`：`O01 → S_i → O01`（**仅一个服务区**，不得跨服务区组批）。
同一服务区可由多个架次分批服务。

### 1.2 最大安全载荷的反解

**去程载货 q、回程空载**，往返能耗：
```
E_g^T(q; i) = E_g(O01→S_i, q) + E_g(S_i→O01, 0)
```
**能量约束取等号**定义最大安全载荷：
```
E_g^T(q_max; i) = (1 − ρ_g) · E_g^use
```

**为什么必须数值反解**：`L_g(q) = L_g0 − (L_g0−L_gF)(q/Q_g)^(3/2)` 中指数为 3/2，
使能耗对 `q` 非线性且无闭式反函数。**解法**：`E_g^T(q)` 关于 q 单调递增
（载荷越大，等效航程越短、能耗越高），用 **brentq 二分**求解。

**最终载荷还要与硬上限取 min**：
```
q_max^safe = min( 能量反解值 , Q_g , 体积对应质量上限 )
```

**必做验证**：反解后回代，断言 `|E_g^T(q_max) − (1−ρ_g)E_g^use| < tol`。

### 1.3 货箱组批（装箱问题）

对每个服务区 `S_i` 独立求解：把该区的货箱集合划分为最少的架次，满足
- 质量：`Σ_{b∈p} m_b ≤ q_max^safe(g, i)`
- 体积：`Σ_{b∈p} v_b ≤ Q_g^vol`
- 型号选择：可选 3 种机型，**机型也参与决策**

### 1.3b ★ 实测结论：**结构载重是主要瓶颈，能量是次要约束**

用真实 DEM + 附件参数跑通地理层与物理层后（`scripts/smoke_physics_real_data.py`，
结果见 `outputs/p0_smoke/q1_single_roundtrip.csv`），得到：

| 事实 | 数值 |
|---|---|
| O01 → 服务区单向距离 | **2808 ~ 8079 m** |
| 航段最高地面高程 | 221 ~ 536 m |
| 巡航海拔 | 271 ~ 586 m |
| 去程爬升高度 | 143 ~ 458 m |
| **A 型受 `Q_g` 约束的服务区数** | **15 / 15** |
| **B 型受 `Q_g` 约束的服务区数** | **14 / 15**（仅 S008 受能量约束） |
| **C 型受 `Q_g` 约束的服务区数** | **10 / 15**（S002/S003/S004/S008/S012 受能量约束） |
| `q_max` 反解的约束紧性 | 相对偏差 **5.6e-15**（精确取等号） |

**建模含义（重要）**：

1. **A 型与 B 型在全部（或几乎全部）服务区都受结构载重上限约束** ——
   也就是说，对这两种机型，`q_max^safe = Q_g`，**最大安全载荷不需要反解**。
   能量约束只在 **C 型（重载、最长满载航程差）** 且距离较远时才起作用。
2. 因此 Q1 的组批方案**主要由 `Q_g` 与装载体积决定**，
   能量约束是"少数派约束"。论文中必须指出这一点，否则会误以为瓶颈在能量。
3. **体积约束可能比质量约束更紧**：例如 A 型 `Q_g=25 kg`、体积 `0.06 m³`；
   饮用水单箱 14 kg / 0.027 m³ → 按质量可装 1 箱（1.79 箱上限），按体积可装 2 箱；
   而生活卫生用品 6 kg / 0.035 m³ → 按体积只能装 1 箱（质量上限 4 箱）。
   **必须逐箱同时检查质量与体积两个约束**（二维装箱）。
4. 最远服务区 S008（8079 m）对 C 型构成能量约束，`q_max = 58.99 kg < Q_g = 80 kg`
   —— 这是 Q1 中**唯一需要真正反解**的情形之一，也是敏感性分析的重点。

> **行动项**：Q1 实现时必须**同时**处理质量与体积二维约束，
> 并输出"每个 (服务区, 机型) 组合实际起作用的约束类型"（质量/体积/能量），
> 作为论文的支撑分析。

**装箱算法（已定，P10）**：目标为**字典序** `min_lex (架次数, 总能耗, 累计作业时间)`
（先少架次、再低能耗、最后压累计作业时间）。实现见 `src/q1_payload_grouping/exact_pack.py`：

1. **按箱型聚合**：同服务区内，同 `(质量, 体积, 首批标记, 期望时间)` 的货箱视为同型
   （题面每类物资单箱参数唯一，故聚合后每区只有 3~5 种箱型，状态空间很小）；
2. **枚举可行批次**：对每个 (服务区, 机型) 组合，枚举满足载质量 / 装载体积 / 返航能量余量的货箱组合，
   并算出该批次的能耗与历时；
3. **字典序 DP**：在"箱型计数状态"上做 DP，记录 `(架次数, 能耗, 累计作业时间)` 的最优前缀。

**下界与 gap**：`sortie_lower_bound()` 给出质量下界与体积下界（**都只在能量可行的机型上取最大容量**，
见 ADR-034），取大者作为该区架次数下界。**实测 15/15 区逐区等于下界，
下界合计 18 = 精确 DP 架次数 18，gap = 0**（`q1_3_sortie_lower_bounds.csv`）。
⇒ **架次数维度可证最优**；**不声称**对"所有可能组批方式"的全局最优。

**结果（P10）**：**18 架次（B×9 + C×9）/ 59.087498 kWh / 累计作业 32676.33 s**；
**FFD（体积降序、首次适应，`grouping.py`）不再是答案路径**，仅作基线对照与下界工具。

### 1.3c ★★ 实测结论：**每个服务区都需要多个架次**，且 C 型是唯一主力

用真实数据构造"每区一架次"的朴素方案（`scripts/smoke_verify_real_data.py`，
结果见 `outputs/p0_smoke/q1_naive_plan_by_service.csv`）：

| 服务区 | 箱数 | 总质量(kg) | 总体积(m³) | 可否单架次 | 说明 |
|---|---|---|---|---|---|
| S001 | **15** | **154.0** | **0.394** | ❌ | 超出全部机型 |
| S002 | 8 | 81.0 | 0.211 | ❌ | 超出全部机型 |
| S003 | 8 | 81.0 | 0.211 | ❌ | 超出全部机型 |
| S004 | 6 | 59.0 | 0.156 | ⚠️ 仅 C | C 型上限 80 kg / 0.25 m³ |
| S005 | 6 | 59.0 | 0.156 | ⚠️ 仅 C | |
| S006–S015 | 3–6 | 25–59 | 0.067–0.156 | ⚠️ 仅 C | A 型 0.06 m³ 装不下 ≥0.067 |

**关键事实（按现行精确 DP 结果校正）**：

1. ~~A 型与 B 型几乎派不上用场~~ → **实测：B 型是"小区首选"**。
   精确 DP 的结果是 **B×9 + C×9**：**9 个 3 箱小服务区（S009–S015 等）各用 1 个 B 型架次**
   （25 kg / 0.067 m³，正好卡在 B 型 30 kg / 0.073 m³ 之内），
   **载货量 ≥ 0.129 m³ 或需拆分的区（S001–S008）用 C 型**，**A 型在本问一次未用**
   —— 因为 A 型装载体积上限只有 **0.06 m³ < 0.067 m³**（最小的 3 箱区也装不下）。
   ⇒ 早先"主力必然是 C 型、A/B 只能打零工"的判断**只对 A 型成立**，
   **B 型在小区上是净收益**（同组批改全 C 型的对照能耗为 **74.2611 kWh**，
   B+C 混编为 **59.087498 kWh**，**省 20.43%**）。
2. **C 型只有 2 架实体机 + 4 组电池**，而全部 80 箱按体积至少需要
   `ΣV / 0.25 ≈ 1.6/0.25 ≈ 7` 个满载架次（按质量算也接近），
   **资源周转（充电）成为 Q2 的真正瓶颈** —— 这正是 Q2 的核心矛盾，
   并与 Q2 的机队规模敏感性结论一致（电池减半或实体机减到 4 架即 INFEASIBLE）。
3. **S001 有 15 箱、154 kg、0.394 m³**，即使 C 型也需**至少 2 个架次**
   （精确 DP 给出 2 个 C 型架次）。组批算法必须支持"同区多架次"。

**对 Q1 的含义**：
- 组批不是"一区一架次"，而是**每区内部的装箱问题**，且要跨机型选择；
- 必须在论文中报告**各服务区的架次数下界**（按质量与体积分别算，取大者，
  且只在能量可行的机型上取）；
- 「往返架次数 / 总能耗 / 累计作业时间」三目标的权衡，会受"是否用 C 型满载"
  与"是否用 B 型凑小批量"显著影响。

### 1.5 返航安全余量敏感性（必答，P10b 起与答案路径同口径）

扫描 `ρ_g ∈ {0.10, 0.20, 0.30, 0.40, 0.50}`，**每个取值都用精确字典序 DP 重跑组批**
（`sweep_reserve_ratio_exact`，`strategy = exact_dp`）；另输出载荷曲线
（`q1_4_payload_vs_rho.csv`，45 条 = 15 区 × 3 机型）与临界值表（`q1_4_critical_rho.csv`）：

| ρ_g | 架次数 | 总能耗 kWh | 累计作业时间 s | 可行 | 无可行组批的服务区数 | 机型 |
|:--:|:--:|:--:|:--:|:--:|:--:|---|
| 0.10 | 18 | 59.087498 | 32676.333 | 是 | 0 | B:9 / C:9 |
| **0.20（附件值）** | **18** | **59.087498** | **32676.333** | 是 | 0 | **B:9 / C:9** |
| 0.30 | 20 | 67.180487 | 36475.134 | 是 | 0 | B:9 / C:11 |
| 0.40 | — | — | — | **否** | **2** | — |
| 0.50 | — | — | — | **否** | **5** | — |

**正确读法（应写进论文）**：ρ_g 从 0.10 松到 0.20（附件值）**不改变任何结果** ——
本实例的组批由**载重体积与结构上限**决定，返航能量余量在这段区间内**不是紧约束**；
到 ρ=0.30 才开始多出 2 个架次（能耗 +13.7%），**不可行从 ρ=0.40 才开始**。
⇒ 附件取 `ρ_g = 0.20` 留有充分裕度。

**临界点的物理解释**：`ρ_g` 越大 ⇒ 允许的往返能耗预算越小 ⇒ 最大安全载荷被压得越低，
直到**某些高海拔/远距离服务区连单箱都飞不到**（`feasible=False`）。
按 `q1_4_critical_rho.csv`（在 **0.05 步长**网格 0.00→0.50 上求解），最先失效的是 **A 型在远距离区**：
**S008 → 0.30**；S002 / S003 / S004 / S012 → **0.35**；S015 → 0.45；其余区 0.50。
B 型的临界值分布在 **0.40~0.50**（最紧为 S003/S004/S008/S012 的 0.40），
C 型为 **0.35~0.50**（最紧为 S004/S008 的 0.35、S002/S003/S012 的 0.40）。

## Q2 异构无人机多点多架次运输调度

### 2.1 决策变量（六元组，须联合确定）

1. 货箱组批
2. **服务区访问顺序**（每架次可访问**一个或多个**服务区）
3. **运输机型** `g`
4. **具体执行无人机**（8 架实体机）
5. **共享电池**分配
6. **各架次开始时刻**

### 2.2 约束

- 货箱不可拆分
- 载质量 / 装载体积
- 返航安全余量 `E_p^T ≤ (1−ρ_g)E_g^use`
- 无人机与共享电池**数量**
- **充电周转**：同一资源任务占用与充电时段**不得重叠**；不同资源可并行
- 时限：**医疗物资期望送达** + **首批保障货箱截止时间**

> ★ 载荷沿架次递减：连续访问多服务区时，每次投送后**从 30 m 作业高度重新爬升**，
> 且后续航段的 `q` 要扣掉已投送的货箱质量。

### 2.3 目标

多目标：配送及时性 + **全部任务完成时间** + 运输能耗 + 架次数

> **全部任务完成时间** = 所有运输无人机完成**最后一个架次并返回 O01** 的**最晚时刻**。

**已定（P10）**：多目标不引入加权系数，而是把**时限读成约束、其余读成字典序目标**：
先把"首批截止 + 逐箱期望送达"作为 CP-SAT 的**硬约束**（可行性门槛），
再在此前提下最小化 `Cmax = max_r(t_r + d_r)`；
架次数与能耗由上游组批阶段按 `min_lex(#架次, 能耗)` 决定（问题一继承而来）。
⇒ 组批与调度**分层求解**，避免"权重调参"式的隐性取舍（ADR-030 的教训）。

### 2.3b 求解结构与实测结果

**求解流程（现行，P10）**：

```
Q1 精确字典序 DP 组批（11 区沿用）
  → 4 个紧时限区（S006/S007/S008/S013）拆"先行小架次 + 余量架次"（18 → 23）
  → CP-SAT 资源区间调度（实体机 / 共享电池 / 起飞时刻，含两阶段充电占用与逐箱硬时限）
  → 独立校验器复核（重算全部物理量）
```

| 模块 | 职责 |
|---|---|
| ★ `solution.py` | **`build_q23()` 方案装配**（Q1 精确 DP 组批 + 4 区拆分 + 调用调度器 + 物理层重算交付耗时 + `verify_plan()` 独立复核） |
| ★ `dispatcher.py` | **CP-SAT 资源区间调度**：可选区间 + `NoOverlap` + 两阶段充电周转占用 + 逐箱硬时限 + 可行解提示；另含"逐档收紧 `Cmax` 上界"的可行性探针 |

**★ 完工时间 7843.2266 s 的最优性说明（必写进论文）**：
给定方案数据的时刻表最晚返回 **7740.19 s**（比本方案小 103 s），

⇒ **103 s 是"时限可行性"的代价，不是"本方案更慢"**（见 ADR-035）。

### 2.3c ★★ 关键发现：**首批时限可以完全满足**（原"不可行"结论已推翻）

> ⚠️ **历史更正**：本节原写"首批时限在本机队下物理不可行、任何调度算法都无法消除"。
> 该结论**建立在建模缺陷之上**（见 ADR-029）：当时 Q2 只调用了 **2 架 C 型**，
> 把题目给的异构机队（A×4+B×2+C×2=**8 架**）白白浪费了 3/4 的并行能力。
> 修正后首批违规为 **0**。**请勿再引用旧结论。**

**为什么可以满足（P10 版，可复算）**

1. **单区首批箱单架次完全可行**：每区首批恰 2 箱（约 17 kg / 0.039 m³），
   **任何机型一次都装得下** ⇒ 问题**不在单架次能力**。
2. **瓶颈是"时限内能同时起飞几架"以及"紧时限架次必须早飞"**：
   - 60 min 档服务区数 = **8**（S001/S002/S006/S007/S010/S012/S013/S014），题目机队 = **8 架**；
   - 初始 SOC 均为 100%，**14 组电池足够 8 架同时起飞**（首轮不受充电周转限制）；
   - 但**组批本身**要先满足时限：S006/S007/S008/S013 若沿用问题一的单一大架次，
     首批箱与医疗箱会迟到 ⇒ 必须拆成"**先行小架次 + 余量架次**"（18 → 23 架次）。
3. **实现条件（现行做法）**：
   - **组批阶段拆分**：4 个紧时限区增开先行小架次（`build_q23()` 内的组批处理，见 ADR-033）；
   - **调度阶段把时限写成硬约束**：CP-SAT 中 `t_r + τ_r ≤ 首批截止`、
     `t_r + τ_r ≤ 每箱期望送达`（`τ_r` 由本仓物理层重算），
     并用已知可行调度作为**可行解提示**避免"证明出更差的 OPTIMAL"（ADR-035）。
4. **实测余量**：首批 **30/30** 达标；期望送达 **80/80** 达标，
   **最紧的期望送达余量只有 11.74 s**（`tightest_expected_slack_s`）；
   超期量 `max_over_expected_s = 0.0`。
5. **不再使用"理论下界 24 架次 / 装载率 79%"这套旧口径** ——
   那是旧求解器（贪心派发 + `consolidate_real()`）的估计，与现行 23 架次方案不可比。
   现行可声明的范围是：**在给定/改进组批下，CP-SAT 求得的最优调度**（见 ADR-035 红线）。

**结论**：首批与期望时限都是**可达的**，
其可达性由"**组批拆分 + 时限硬约束调度**"共同保证，不是"资源硬约束下的物理必然"。
**不要**再写"首批时限物理不可行"（ADR-029 时代的旧结论）。

## Q3 通信约束下的运输与中继联合调度

### 3.1 新增决策变量

- 中继无人机的**悬停位置**（平面位置 + 飞行海拔）—— 连续三维变量
- **服务时段**
- **能源组件分配**

### 3.2 连续通信约束（★ 本题最硬的新约束）

> 运输无人机在**爬升、巡航、下降及物资投送**阶段**均应保持连续通信**。

形式化：设架次 p 的轨迹为 `Traj_p(t)`，要求
```
∀ t ∈ [t_start(p), t_end(p)] :  comm_state( Traj_p(t) ) ≠ 中断
```
其中
```
comm_state = 直连   若 A(运输机 ↔ G01) = 1
           = 中继   若 直连不可用 且 A(运输机 ↔ 中继机) = 1 且 A(中继机 ↔ G01) = 1
           = 中断   其余
```

**实现要点**：
- 必须**沿航段逐时刻采样**（不能只查端点）—— 见规范 ADR-007
- **采样步长须做敏感性分析**（步长太大漏判，太小算不动）
- 中继需**两段链路同时可用**，且**不允许多跳**
- 每架运输机同时刻**只由 G01 或一架中继**保障

### 3.3 中继悬停位置

- 悬停位置必须**位于 DEM 覆盖范围内**
- 悬停**离地高度 ≤ 附件规定上限**
- 往返悬停位置的地形净空按航段规则确定（最高点 + 50 m）
- 需满足**返航电量要求**

**待填**：悬停候选点的离散化方式（网格步长）、选址与调度的耦合求解策略。

### 3.3b ★★ 实测结论：真实地形下 **12/15 条航段存在直连中断**

**这条结论决定了 Q3 的形态**：

1. **中继无人机是必需的，不是可选项** —— 12 条航段存在通信中断，
   而题目硬性要求"爬升、巡航、下降及物资投送**全程**保持连续通信"。
2. **中断集中在远距离航段**（S002/S003/S008/S012 中断占比 44%~45%），
   近距离航段（S001/S006/S011，均 < 3.2 km）无中断。
   → 中继服务时段的规划应以**远距离架次**为重点。
3. ★ **本计算的"中断占比"是下界**：此处只按**巡航海拔**判定，
   而无人机投送时会下降到服务区作业高度（地面 + 30 m），
   若把爬升段与下降段也计入，中断时间会更长。
   ⇒ **现行实现已覆盖完整轨迹**（爬升/巡航/下降/投送四阶段），见 3.5 的 `timeline.py`。
4. ★ 判定步长 250 m 属粗扫；**现行实现取 0.25 s 时间步长、60 m 视线步长**
   （`sample_dt_s` / `los_step_m`，共 99889 个样本），
   并如实声明"有限采样不构成连续时间的数学证明"。

### 3.3c 链路预算的关键定量结论（供中继选址用）

| 链路 | 双向门限 | 自由空间可达距离 | 含 10 dB 遮挡后 |
|---|---|---|---|
| 直连（运输机↔G01） | 122 dB | **12.511 km** | 3.956 km |
| 中继接入（运输机↔中继） | 116 dB | **6.270 km** | 1.983 km |
| 中继回传（中继↔G01） | 126 dB | **19.828 km** | 6.270 km |

> ★ **中继接入段是最弱一环（116 dB）**，比直连低 6 dB。
> 因此中继必须**靠近运输无人机**（≤ 6.27 km），而回传段很宽松（≤ 19.83 km）。
> 这直接决定了悬停位置的可行域形状：**贴近作业空域、而非贴近网关**。
>
> 又因为本场景远距离航段普遍存在遮挡（见 3.3b），
> 中继的核心价值是**抬高视线高度以越过山脊**，而不是缩短距离。

### 3.4 目标

物资配送及时性 + **联合任务完成时间** + 运输与中继总能耗 + 两类无人机使用架次

> **联合任务完成时间** = 所有**运输无人机和中继无人机**完成最后一个架次并返回 O01 的**最晚时刻**。

### 3.5 求解结构与实测结果

**★ 建模关键：把"连续轨迹 × 连续选址"降维**

题目要求轨迹上**每一时刻**都满足通信。若逐时刻独立选址，问题退化为不可解的
连续最优控制。我们采用**可验证的充分条件**：

> 对某架次，若存在**一个**悬停点 `P`，使得
> `∀ t ∈ [开工, 返回]：直连可用 ∨ (接入(P) 可用 ∧ 回传(P) 可用)`
> 则该架次由一架中继在 `P` 处全程保障即可。

于是只需"离散候选点 × 时间采样"两次扫描。若单点无法覆盖，
退化为**按时段分段覆盖**（多架中继接力）—— 题目允许不同时刻由不同中继保障
（"每架运输机在**任一时刻**只能由 G01 或一架中继保障"）。

## Q4 救援任务分区与资源配置优化方案

### 4.1 硬约束（违反即无效）

- 15 个服务区划分为 **2 组** 与 **3 组** 两种方案
- 每个服务区**必须且只能**属于一个任务组；**每组至少一个服务区**
- ★ **保持 Q3 已确定的货箱组批、服务区访问顺序、运输与中继任务安排、通信保障关系不变**
- ★ **若同一运输架次同时涉及多个服务区，则这些服务区应划入同一任务组**
- 各任务组**仅承担本组**服务区的任务
- **任务执行期间各类资源不得跨组调配**

### 4.2 建模关键：先聚类架次，再归组服务区

因为"同架次的多服务区必须同组"，**不能先分服务区**（会导致方案不可行）。
正确顺序：
```
Q3 方案 → 提取架次集合 → 求"原子单元"（同架次服务区集合）
        → 对原子单元做划分（k = 2 或 3 类）
        → 校验：服务区互不重叠且并集 = 全部 15 个
```
> ★ 若 Q3 中存在一个架次同时服务了本应分属不同组的服务区，则该服务区集合构成
> **不可分的原子单元**。因此**必须先把原子单元求出来再划分**，
> 直接对 15 个服务区做 k-means/枚举会产生不可行方案。

### 4.3 资源核算（每组独立）

| 资源 | 需求 |
|---|---|
| 运输无人机 | 组内架次并行的峰值需求（`_parallel_peak`，首尾相接不算重叠） |
| 共享电池 | 考虑充电周转后的需求（分机型，`batteries_required`） |
| 中继无人机 | ★ **先做唯一归属** `assign_relays_to_groups()`，再取**本组名下**中继任务的并行峰值 |
| 中继能源组件 | 同组名下中继的充电周转需求 |

> ★ **为什么中继必须先归属**：一个中继架次常同时保障**跨多个组**的运输架次
> （本轮 `R01-1` 保障全部 23 个架次）。若按"保障对象全在本组"判据，
> 任何真分组都认领不到中继 ⇒ 会算出"中继需求 0 架"的荒谬结论（ADR-037）。
> 归属规则：**覆盖架次最多**的组优先，平票取服务区交集更多者，再取组号小者；
> 每个中继只计入一次。**代价是该口径偏乐观**（组间中继依赖不补偿），须随结论声明。

### 4.4 对比维度（4 项，必答）

| 维度 | 度量 |
|---|---|
| 资源配置规模 | 四类资源总需求（2 组 vs 3 组） |
| **资源冗余** | 现有库存 − 组内需求（逐组、逐类） |
| **组间工作量均衡** | 各组工作量（架次数 / 时长 / 能耗）的方差或最大最小比 |
| **资源缺口** | 负冗余；须给出**原因** |

**已填（P10b）**：分区方案、四类资源数值、冗余与缺口、均衡指标见 **4.5**
（数据来自 `outputs/q4/tables/q4_方案对比.csv`、`q4_资源缺口.csv`、`q4_逐组明细.csv`、`q4_分区配置.csv`）。

### 4.5 ★★ 实测结论：**15 个原子单元 ⇒ K=2 与 K=3 均可直接得到（改动 0 架次）**

> ⚠️ **本节的三条历史更正（务必按现行版引用）**：
> ① 旧版曾写"按题目规则**不存在**合法的 2 组或 3 组分区、只能 K=1" ——
> 那是 Q3 更早方案（35 架次 / 21 个多点架次 / 15 区串成 1 个分量）的产物，**已推翻**；
> ② P9 之后曾写"3 个原子单元 / 6 个桥接架次 / 资源 33-34-38" ——
> 那是 **25 架次 / 12 个多点架次** 旧方案的产物，**现已作废**；
> ③ P10 首轮曾写"资源 **28-28-30**、缺口 **B 型电池 +1**" ——
> 那是**中继归属 bug**（K=2/K=3 的中继被记成 0 架）时期的中间值，**现已作废**（ADR-037）。
> 现行（P10b）：Q3 的 **23 个架次全部为单点路线** ⇒ **15 个原子单元 / 0 个桥接架次**，
> 资源 **28 / 29 / 30**。

**推导（严格）**：
题目规则 3 要求"**若同一运输架次同时涉及多个服务区，则这些服务区应划入同一任务组**"。
把所有此类"同架次"约束求并，即得服务区的**连通分量**（原子单元）：

- Q3 方案共 **23** 个运输架次，其中**多点架次 = 0**（`n_multi_stop_sorties = 0`）
- 图上没有任何边 ⇒ **15 个连通分量**（每个服务区各自成组，`q4_原子单元.csv` U01–U15）
- ⇒ 合法组数 **K ∈ [1, 15]**（单元不可再拆，多个单元可合并成一组）
- ⇒ **K=2 与 K=3 均可由原子单元直接合并得到，改动 0 个架次**
  （`partition_feasible_k2 = partition_feasible_k3 = true`，`k2/k3_edits_required = 0`）

**桥接架次**（移除后分量数即增加）：**0 个** —— 单点架次不连接任何两个服务区，
故 `q4_桥接架次.csv` 只有表头。桥接清单的用途不变：
作为**进一步细化分区粒度的备用依据**（每拆一个桥接架次可多得到 1 个可选分组粒度）。

**各方案资源与代价对比**（组内独立排程、资源不跨组；★ P10b 重算）：

| 方案 | 改动架次数 | 运输无人机 | 共享电池 | 中继无人机 | 中继能源组件 | **资源总量（台·组）** | 组间不均衡 | 单组最大工作量 |
|---|:--:|:--:|:--:|:--:|:--:|:--:|:--:|:--:|
| **K=1（全部 15 区一组）** | 0 | 8 | 15 | 2 | 3 | **28** | 0.0000 | **11.27 h** |
| **K=2（直接可行）** | **0** | 9 | 15 | 2 | 3 | **29** | 0.2289 | **6.28 h** |
| **K=3（直接可行）** | **0** | 10 | 15 | 2 | 3 | **30** | 0.8425 | **5.62 h** |

**★ 关键结论（反直觉但可解释）**：

1. **K=2 需要 +1 架运输机**（8→9）：把 15 区切成 **7 + 8** 后，
   两组各自的运输机并行峰值之和超过了整队一组时的峰值（规模效应部分丧失）；
   **电池与中继资源不变**（15、2、3）。
2. **K=3 再 +1 架运输机**（9→10）：切成 **8 + 3 + 4** 后，G1（8 区）与 G2（3 区）
   各自都需要 C 型机（分别 2 架与 1 架），机型池无法再互相借用。
3. **分区会加剧组间不均衡**：不均衡度 0 → **0.2289** → **0.8425**。
4. **分区显著降低单组作业压力**：单组最大工作量 **11.27 → 6.28 → 5.62 h**
   （K=3 比 K=1 低约 **50%**）。这对"多支救援队同时作业、各自独立补给"的现场组织方式有利 ——
   是一条**有工程指导意义**的结论。

**资源缺口（与现有库存对比，逐机型；数据源 `q4_资源缺口.csv`）**：

| 方案 | 运输无人机（需求/库存） | 共享电池（需求/库存） | 中继无人机 | 中继能源组件 | **缺口合计** |
|---|---|---|---|---|---|
| **K=1** | A 4/4、B 2/2、C 2/2 ⇒ 0 | A 6/6、B 4/4、**C 5/4（缺 1）** | 2/2（0） | 3/6（冗余 3） | **C 型电池 +1 组** |
| **K=2** | A 4/4、**B 3/2（缺 1）**、C 2/2 | A 6/6、B 4/4、**C 5/4（缺 1）** | 2/2（0） | 3/6（冗余 3） | **B 型运输机 +1 架、C 型电池 +1 组** |
| **K=3** | A 4/4、**B 3/2（缺 1）**、**C 3/2（缺 1）** | A 6/6、B 4/4、**C 5/4（缺 1）** | 2/2（0） | 3/6（冗余 3） | **B 型运输机 +1 架、C 型运输机 +1 架、C 型电池 +1 组** |

> ★ **本轮缺口的性质与旧版完全不同**：
> - **中继机与中继能源组件在三种分区下都不缺**（需求 2 架 / 3 组，库存 2 架 / 6 组）；
>   旧版"中继缺口 4 架"（ADR-031 时代）**已作废**；
> - 短板是 **C 型电池（三种分区都缺 1 组）**，以及 **K≥2 起的 B 型运输机**
>   （K=3 还要再加 1 架 C 型运输机）；
> - 现行 Q3 的通信缺口（928 个中断样本）**不是"缺中继机"**，
>   而是**站位时机**问题（见 **ADR-036**：4 中继对照反而更差）。
>
> ## ★★ 中继归属的**乐观口径**（ADR-037，必须与缺口结论并列写出）
>
> 中继资源由 `assign_relays_to_groups()` 先做**唯一归属**：每个中继架次归给
> "它保障的、落在该组的运输架次最多"的那一组（平票取与组内服务区交集更多者，再取组号小者），
> 同一中继**只被一个组计入一次**，避免总量被重复放大。
> 本轮 `R01-1` 保障全部 **23** 个架次 ⇒ 它归给"架次最多"的组
> （K=2 归 G1、K=3 归 G1），因此 **K=2 的 G2、K=3 的 G2/G3 名下中继为 0**，
> 而它们的通信**实际仍依赖 G1 的中继** —— 本核算**不额外补偿**，
> 这是"资源不得跨组调配"下**偏乐观**的读法（`q4_逐组明细.csv` 可见逐组中继为 3/0、3/0/0）。
>
> ⚠️ **历史坑**：旧 `group_resources()` 要求"中继保障的运输架次**全部**在本组"才计入，
> 于是任何真分组都认领不到 `R01-1` ⇒ K=2/K=3 曾算出**中继 0 架 / 0 组**；
> 叠加的第二个 bug 是 `run_q4.load_q3()` 把 `q3_通信保障.csv`（**47 条** pair）
> 读成一对一字典（后行覆盖前行）。两处均已修（ADR-037）。
>
> ⚠️ 注意 `group_resources` 按**并行峰值 + 电池周转**核算（"独立执行所需储备"），
> 与 Q2/Q3 的实际排程占用是两个不同口径，论文中须分别说明。
> 其中"首尾相接不算重叠"是刻意约定：同一架无人机刚返回即可接下一架次。

**若要缓解缺口**，可选途径（可作为改进方向讨论）：
- **按机型补齐**：优先补 **C 型电池 +1 组**（三种分区都缺，且不随 K 变化）；
  K=2 还需补 **B 型运输机 1 架**，K=3 再补 **C 型运输机 1 架**；
- **联合优化中继站位时机**（而不是增加中继架次）以提高 T10/T15/T18/T20 的覆盖（ADR-036）；
- 或允许组间借用备用电池/中继（放宽"资源不得跨组调配"，同时也就消除了上面那条乐观口径）。
