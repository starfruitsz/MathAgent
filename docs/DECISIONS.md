## 已决

| # | 决策 | 理由 | 影响 | 状态 |
|:--:|---|---|---|---|
| **ADR-001** | 地理计算用 `rasterio` + `geopandas` + `pyproj` + `shapely`，**不引入** `richdem` / `elevation` | 后两者在 Python 3.13 上安装风险高；`elevation` 还需**联网下载 SRTM 瓦片**，与"不得引入其他数据"的红线冲突。附件已直接提供 30 m DEM | `src/geo/` | 采纳 |
| **ADR-002** | 优化用 `ortools` + 自研启发式，**不引入** `vrpy` | `vrpy` 依赖重、版本兼容风险；本题约束高度定制（充电周转、连续通信、载荷递减），通用 VRP 库收益有限 | Q2 Q3 | 采纳 |
| **ADR-003** | **所有航段量预计算并缓存**到 `data/processed/leg_cache.parquet` | DEM 采样是热点；Q2/Q3 求解器会反复查询同一航段，重算是主要性能瓶颈 | 性能 | 采纳 |
| **ADR-004** | 最大安全载荷用**单调性 + `brentq` 反解**，不用解析近似 | `L_g(q)` 的 3/2 次幂使能量对 `q` 非线性，**无闭式反函数** | Q1 | 采纳 |
| **ADR-005** | 内部**一律 SI 单位**，进出附件时换算并登记 | FSPL 要 km/MHz、航程要 m，混用是单位错误的根源（尤其 `D` 的 m→km） | 全部 | 采纳 |
| **ADR-006** | 可行性校验器**独立于求解器**，且必须有**负样本测试** | 求解器与校验器同源会"自证清白"；负样本测试才能证明校验器真的能抓错 | R8 | 采纳 |
| **ADR-007** | 连续通信判定**沿航段逐时刻采样**，不用端点近似 | 题目明确要求"爬升、巡航、下降及投送阶段均应保持连续通信"；端点判定会漏掉中途被山体遮挡的时段 | Q3 | 采纳 |
| **ADR-008** | Q4 分区**先聚类架次（原子单元）再归组服务区** | "同架次的多服务区必须同组"是硬约束；先分服务区会产生不可行方案 | Q4 | 采纳 |
| **ADR-009** | 提交铁律由 `scripts/commit.ps1` 强制（含收工自检） | 人工易忘；脚本在未推送时抛异常，把规范变成可执行的门禁 | R1 | 采纳 |
| **ADR-010** | 被推翻/已废弃的 D 题方案归档至 `docs/legacy_D题/`，**不就地删除** | 保留决策轨迹，便于回溯"为什么否掉某个方案"；避免后续 agent 重复踩同一个坑 | 仓库卫生 | 采纳 |
| **ADR-011** | 附件坐标先按原样读入，**统一在 `geo/crs.py` 投影到米制坐标系**后再算距离 | 经纬度直接算欧氏距离是错的；投影必须在单一入口完成，避免各处重复实现 | `src/geo/crs.py` | 采纳 |
| **ADR-012** | `discover.py` 的清单输出**必须写到被扫描目录之外** | 否则第二次扫描会把上一轮清单当输入数据，结果自我污染、不可复现 | 脚本用法 | 采纳 |
| **ADR-013** | `discover.py` 忽略 `.gitkeep` / `~$*` / `.tmp` | 仓库默认只有 `.gitkeep`，不忽略会误判"数据已就绪" | 数据就绪判定 | 采纳 |
| **ADR-014** | 依赖锁定为**当前环境实测通过**的版本，而非 PyPI latest | 保证本机可复现；升级需单独验证并提交 | 环境可复现性 | 采纳 |

**新增已决**：

| # | 决策 | 理由 | 影响 |
|:--:|---|---|---|
| **ADR-015** | 以 `逐箱货箱清单`（80 箱）为**唯一权威**箱数据源，`数据` sheet 仅作交叉核对 | 80 箱与题目"80 个不可拆货箱"一致；已核验两表 53 组 (服务区,物资类型) **零差异** | Q1–Q4 |
| **ADR-016** | 必须按 `结果提交模板.xlsx` 的 6 个 sheet 设计数据结构 | 它是**交付格式的硬约束**，且题目正文未提及，事后重构代价高 | 全部 |
| **ADR-017** | `ρ_g = 20%` 解读为 `E_p^T ≤ (1−0.20)·E_g^use`，并输出 `返航SOC（%）` 字段 | 提交模板要求 `返航SOC`；「返航电量下限 20%」即安全余量 | Q1–Q3 |
| **ADR-018** | 附件用单一 `G` 表示天线增益 → 公式中 `G_t = G_r = G`（各主体取自身值） | 附件只有一列"天线增益（dBi）" | `comms/link.py` |
| **ADR-019** | **DEM 是 DSM（数字表面模型，含植被/建筑），不是裸地 DEM** —— 按原样使用，不"去建筑" | `镇龙乡地理空间数据说明.pdf` 明确："DEM 来源于 Copernicus DEM GLO-30，**为数字表面模型（DSM）**"。DSM 高程 ≥ 真实地形，用于净空与遮挡判定**偏保守**（更安全），符合救援场景 | `geo/dem.py`、`geo/los.py` |
| **ADR-020** | 爬升能耗系数 `0.72` 解读为**效率**：`E_up = m·g·h⁺ / η_up`，η_up=0.72 | 附件列名为"**爬升能耗效率**"，且下降为 0（不单独计能耗）→ η 是"机械功→电能"的效率。但附件只给列名、未给定义，故**在 `config` 中显式暴露该解读**，并在论文中说明；若改为乘法则只需改一处 | `physics/energy.py` |
| **ADR-021** | 运输机**水平巡航能耗由航程反推**：`E_hor = (d / L_g(q)) · E_g^use` | 附件只给"空载/满载标准航程"与"电池可用能量"，**未给巡航功率**（中继机才给功率）。由航程定义反推是唯一自洽的做法，且使安全余量约束退化为 `d ≤ (1−ρ)·L_g(q)`，物理意义清晰 | `physics/energy.py` |
| **ADR-022** | 论文公式**统一用 MathType 对象**呈现：类 LaTeX → OMML → `Equation.DSMT4`（正文/行内/表内全部覆盖） | 用户明确要求"公式使用 MathType 生成，涉及正文嵌入的表格嵌入的公式"；MathType 既能被 Word 原生识别为**可编辑公式**，又能保证任何环境（含打印/PDF）显示一致 | `src/report/equations.py` |
| **ADR-023** | 公式预览图缩放取 `preview_pt_per_px = 0.23`，且**必须自行重绘预览图** | 库默认 0.15 使公式小于正文；而更大的问题是库把 `mml:math` 原样嵌入 HTML，HTML 解析器不做命名空间解析 → 公式退化成一行普通文字，**上下标与分式全部丢失**。本仓库改为去前缀后重绘（`render_previews`）并按新尺寸写回（`reembed_previews`）；比例在 300 dpi 成品 PDF 上逐行量测标定为 0.23 | `src/report/equations.py` |
| **ADR-024** | 表格统一为**三线表**（顶线/表头下线/底线，无竖线），列宽按内容自适应且列宽比 ≤4:1，≥9 列自动降字号 | 用户要求"表格格式参照参考文稿2"；等宽列会让中文表头逐字换行、把表撑高甚至跨页 | `build_paper.py::TABLE` |
| **ADR-025** | 图表同页采用"图片段落 `keepNext` + 表题 `keepNext` + 题注 `keepLines`"，**不给图题设 `keepNext`** | 若图题也 `keepNext`，"图+题注+后文"会连成不可分割的整体，放不下时整块被推到下页，制造大片留白（实测最差 22.7 cm 空白） | `build_paper.py::FIGURE` |
| **ADR-026** | 章节分页写入 `Heading 1` 样式的 `pageBreakBefore`，**不逐处插分页符** | 样式级控制一处生效、目录与导航一致，避免"某章漏加分页符"这类不一致 | `build_paper.py::setup` |
| **ADR-027** | 插图内部**不再写图号**（删除 15 处 `fig.suptitle("图 N …")`） | 论文 docx 已由 `FIGURE()` 统一生成题注；插图内再写会与正文编号冲突（实测出现"图 7"与"图 20"同指一张图） | `make_figures.py` / `make_figures2.py` |
