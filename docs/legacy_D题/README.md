# D 题历史 / 废弃方案归档（legacy_D题）

> **本目录只读**。存放**被推翻或已废弃的 D 题方案**，不参与当前求解流程。

---

## 这个目录是干什么的

D 题（山区洪涝灾害下无人机运输与通信协同优化）的建模过程中，会不断出现
"试过了、但不 work"或"推导后发现不成立"的方案。这些方案的**结论**会被丢弃，
但**弃用原因**往往比结论本身更有价值 —— 它能避免后续 agent 重复踩同一个坑。

因此约定（见 `OPS_SPEC_D题.md` 的 ADR-010）：

> 被推翻的方案**不就地删除**，而是移入本目录，并**注明弃用原因**。

---

## 归档规范

每个归档项应包含：

| 项 | 要求 |
|---|---|
| 文件名 | `<主题>_<状态>.md`，例如 `q3_relay_siting_grid_废弃.md` |
| **原方案** | 简述当时的建模思路与关键公式 |
| **试过什么** | 具体做了什么实验（数据规模、参数） |
| **为什么弃用** | ★ **必须写清楚**：数值结果不支持？违反题目硬约束？计算量不可接受？ |
| **可复用的部分** | 如果有哪部分仍可用于新方案，明确指出 |
| **关联** | 指向 `docs/MODEL_NOTES.md` / `docs/DECISIONS.md` 中的对应条目 |

代码类归档（`.py`）保留原样，并在文件头部注释中写明弃用原因。
