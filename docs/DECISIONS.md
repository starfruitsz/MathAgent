# 决策记录（ADR）— D 题

> 每做出一项影响后续工作的技术决策，在此追加一行并**提交推送**（铁律 R1）。
> 格式：`ADR-nnn | 决策 | 理由 | 影响范围 | 状态`

## 已决

| # | 决策 | 理由 | 影响 | 状态 |
|:--:|---|---|---|---|
| **ADR-001** | 地理计算用 `rasterio` + `geopandas` + `pyproj` + `shapely`，**不引入** `richdem` / `elevation` | 后两者在 Python 3.13 上安装风险高；`elevation` 还需**联网下载 SRTM 瓦片**，与"不得引入其他数据"的红线冲突。附件已直接提供 30 m DEM | `src/geo/` | 采纳 |
| **ADR-002** | 优化用 `ortools` + 自研启发式，**不引入** `vrpy` | `vrpy` 依赖重、版本兼容风险；本题约束高度定制（充电周转、连续通信、载荷递减），通用 VRP 库收益有限 | Q2 Q3 | 采纳 |
| **ADR-003** | **所有航段量预计算并缓存**到 `data/processed/leg_cache.parquet` | DEM 采样是热点；Q2/Q3 求解器会反复查询同一航段，重算是主要性能瓶颈 | 性能 | 采纳 |
| **ADR-004** | 最大安全载荷用**单调性 + `brentq` 反解**，不用解析近似 | `L_g(q)` 的 3/2 次幂使能量对 `q` 非线性，**无闭式反函数** | Q1 | 采纳 |
| **ADR-005** | 内部**一律 SI 单位**，进出附件时换算并登记 | FSPL 要 km/MHz、航程要 m，混用是单位错误的根源（尤其 `D` 的 m→km） | 全部 | 采纳 |
| **ADR-006** | 可行性校验器**独立于求解器**，且必须有**负样本测试** | 求解器与校验器同源会"自证清白"；负样本测试才能证明校验器真的能抓错 | R8 | 采纳 |
| **ADR-007** | 连续通信判定**沿航段逐时刻采样**，不用端点近似 | 题目明确要求"爬升、巡航、下降及投送阶段均应保持连续通信"；端点判定会漏掉中途被山体遮挡的时段 | Q3 | 采纳 |
| **ADR-008** | Q4 分区**先聚类架次（原子单元）再归组服务区** | "同架次的多服务区必须同组"是硬约束；先分服务区会产生不可行方案 | Q4 | 采纳 |
| **ADR-009** | 提交铁律由 `scripts/commit.ps1` 强制（含收工自检） | 人工易忘；脚本在未推送时抛异常，把规范变成可执行的门禁 | R1 | 采纳 |
| **ADR-010** | 被推翻/已废弃的 D 题方案归档至 `docs/legacy_D题/`，**不就地删除** | 保留决策轨迹，便于回溯"为什么否掉某个方案"；避免后续 agent 重复踩同一个坑 | 仓库卫生 | 采纳 |
| **ADR-011** | 附件坐标先按原样读入，**统一在 `geo/crs.py` 投影到米制坐标系**后再算距离 | 经纬度直接算欧氏距离是错的；投影必须在单一入口完成，避免各处重复实现 | `src/geo/crs.py` | 采纳 |
| **ADR-012** | `discover.py` 的清单输出**必须写到被扫描目录之外** | 否则第二次扫描会把上一轮清单当输入数据，结果自我污染、不可复现 | 脚本用法 | 采纳 |
| **ADR-013** | `discover.py` 忽略 `.gitkeep` / `~$*` / `.tmp` | 仓库默认只有 `.gitkeep`，不忽略会误判"数据已就绪" | 数据就绪判定 | 采纳 |
| **ADR-014** | 依赖锁定为**当前环境实测通过**的版本，而非 PyPI latest | 保证本机可复现；升级需单独验证并提交 | 环境可复现性 | 采纳 |
